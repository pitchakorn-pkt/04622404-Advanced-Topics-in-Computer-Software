# LAB07 — Agentic AI System II: รอดไม่รอด (rod-mai-rod) (งานทีม)

[English](README.md) · ภาษาไทย

**repo ของทีม: [pitchakorn-pkt/rod-mai-rod](https://github.com/pitchakorn-pkt/rod-mai-rod)** · เว็บที่ใช้งานจริง: https://rod-mai-rod.tntproduction.tech

รอดไม่รอด คือเว็บวางแผนเดินทางทางถนนในประเทศไทยให้ปลอดภัย ทำเป็นทีม 8 คน ในงาน DL-07
*Agentic AI System II* (ผู้ช่วยเดินทางอัจฉริยะและเหตุฉุกเฉิน) ทุกทริประบบจะเช็กเส้นทาง
พยากรณ์อากาศ ณ ชั่วโมงที่รถไปถึงแต่ละจุด น้ำท่วมจากดาวเทียม และภัยใกล้เส้นทาง แล้วตัดสินด้วยกฎว่า
เดินทางได้ เปลี่ยนเส้นทาง เลื่อนเวลา หรือควรเลี่ยง มีผู้ช่วย AI "น้องกิเลน" สร้างและแก้ทริปผ่านแชทได้
ตัวระบบคือหน้าเว็บ Next.js บริการ Python 6 ตัว และ PostgreSQL ขึ้นด้วย `docker compose` ชุดเดียว

**ส่วนของผม: โมดูล 5 — Routing Engine และตั้งแต่ 3 ต.ค. ดูแลทั้งโปรเจกต์** สองสัปดาห์แรกผมรับผิดชอบ
service เดียวคือ `services/routing-engine/` หลังทุกโมดูลขึ้น `main` แล้ว (#86) repo ถูกโอนมาอยู่ในบัญชีของผม
และผมรับช่วงดูแลทั้งโปรเจกต์ต่อ ได้แก่ แก้ปัญหาที่ทีม อาจารย์ และคนที่ลองใช้เว็บเจอหลัง deploy รอบแรก
เพิ่มการเข้าสู่ระบบด้วย Google นำทุกการแก้ขึ้น `main` และเขียนเอกสารใหม่ รายละเอียดของตัวระบบและผลที่วัดได้
อยู่ใน README ของทีม ([`README.md`](README.md) ใต้เส้นคั่น ซึ่งเป็นภาษาไทยอยู่แล้ว) ส่วนหน้านี้อธิบายว่าผมทำอะไรไปบ้าง

## สิ่งที่ผมทำ

ส่วนที่ต้องลงแรงจริง

- **เวลาที่ไปถึงแต่ละจุด ไม่ใช่อากาศตอนกดวางแผน** ทริปไกลใช้เวลาหลายชั่วโมง service จึงไล่ polyline
  ทั้งเส้นด้วยระยะ haversine วางจุดทุกประมาณ 20 กม. และแบ่งเวลาของแต่ละช่วงตามสัดส่วนระยะ
  กรุงเทพ > เชียงใหม่ ส่งจุดไปให้ risk-decision 72 จุดในคำขอเดียว รวมทุกเส้นทาง
- **OSRM สาธารณะส่งข้อมูลมาไทยช้า** ขอแบบ `polyline` แทน GeoJSON ทำให้คำตอบหนึ่งครั้งเล็กลงจาก
  277 KB เหลือ 43 KB การวางแผนที่ใช้เวลา 47 วินาทีตอนรวมระบบ เกิดจาก timeout ของ HTTP นับแยกทีละการอ่าน
  ตอนนี้เพดาน 12 วินาทีจึงเป็นเวลารวมจริงที่คุมด้วย thread pool ถ้าหมดเวลา ระบบโหลดต่อเบื้องหลังแล้วเก็บลง
  cache (key คือพิกัดปัดทศนิยม 3 ตำแหน่ง) ไว้ให้คำขอถัดไป และ HTTP 429 กลายเป็น error `RATE_LIMITED` ที่อ่านเข้าใจ
- **เส้นเลี่ยงเมื่อ OSRM ไม่มีเส้นอื่นให้** ถ้าเส้นทางเดียวที่มีเสี่ยงระดับ HIGH service จะดันจุดผ่านออกไป
  50 กม. ทั้งสองข้างของจุดเสี่ยง แล้วเลือกเส้นที่เร็วที่สุดที่ห่างจุดนั้นเกิน 20 กม. และช้ากว่าเส้นเดิม
  ไม่เกิน 1.5 เท่า ตัดจุดผ่านที่อยู่นอกประเทศไทยทิ้ง ทั้งคำขอต้องเสร็จใน 42 วินาที เพราะ api-backend รอ 45
  และจะลองเส้นเลี่ยงก็ต่อเมื่อยังเหลือเวลาพอ

service นี้มีเทสต์ pytest 55 ข้อ ทุกข้อรันบน fixture ที่บันทึกไว้

### 2. รับช่วงดูแลโปรเจกต์ และแก้ปัญหาที่เจอหลัง deploy รอบแรก (3–6 ต.ค.)

หลัง deploy รอบแรก ปัญหามาจาก 3 ทาง คือทีม อาจารย์ และคนที่ลองใช้เว็บ ผมแก้บน branch เดียว
ปัญหาละหนึ่ง commit (รวม 16 commit) แล้วนำขึ้นเป็น [#89](https://github.com/pitchakorn-pkt/rod-mai-rod/pull/89)
→ `main` [#90](https://github.com/pitchakorn-pkt/rod-mai-rod/pull/90) ตามด้วยการแก้แชทและ Google sign-in
ใน [#91](https://github.com/pitchakorn-pkt/rod-mai-rod/pull/91) และ [#92](https://github.com/pitchakorn-pkt/rod-mai-rod/pull/92)
→ [#93](https://github.com/pitchakorn-pkt/rod-mai-rod/pull/93)

- **เว็บค้างตอนมีคนใช้แค่ 3 คน** ผมวัดทีละชั้นตามที่อาจารย์ถาม คือ server, backend, ฐานข้อมูล และ AI
  บน image ที่ใช้ deploy โดยจำกัด CPU 1 core แรม 2 GB ฐานข้อมูลไม่ใช่ปัญหา แต่ CPU เต็ม และ api-backend
  กินไป 82% ต้นเหตุมี 2 ข้อ คือทุกครั้งที่เรียก service อื่นสร้าง HTTP client ใหม่และโหลดใบรับรอง SSL ใหม่
  (~110 ms CPU ต่อครั้ง หน้าหลักทำ 9 ครั้ง) และ bcrypt 12 รอบใช้ CPU 300 ms ต่อการ login
  แก้ด้วย client ตัวเดียวต่อ service และ bcrypt 10 รอบ (รหัสเดิมแปลงให้เองตอน login ครั้งถัดไป)
  **ผู้ใช้ 20 คนพร้อมกันจาก 33.8 วินาที เหลือ 3.9 วินาที** ต่อหนึ่งรอบการใช้งาน
- **ทั้งระบบใช้แรมราว 650 MB** เกินแพ็กเกจ Render 512 MB จึงย้ายไปรันด้วย `docker compose`
  บนเซิร์ฟเวอร์แรม 2 GB ของเพื่อนในทีม และผมเอาการตั้งค่า Render ออก
- **แชทพูดไม่ตรงความจริง** ตอบว่า "สร้างทริปแล้ว" ทั้งที่ไม่ได้สร้าง ถาม "ถ้าเลื่อนไปจะดีไหม" แล้วเลื่อนจริง
  สร้างทริปเดิมซ้ำ ขากลับไปจบที่กรุงเทพแทนจุดเริ่มต้น และไม่ใช้ GPS ตอนนี้ทุกข้อบังคับด้วยโค้ด ไม่ฝากไว้ที่
  prompt ได้แก่ ตอบว่าสร้างแล้วได้ก็ต่อเมื่อเครื่องมือทำสำเร็จจริง คำถามสมมติไม่แก้ทริป กันทริปซ้ำ
  ขากลับคือขาไปที่สลับต้นทางกับปลายทางตรงตัว และใช้ GPS เป็นต้นทางทั้งในฟอร์มและแชท
  ชุดทดสอบแชท: **30/32 → 32/32** และ **33/34 → 34/34**
- **แชทแนะนำความปลอดภัยผิด** บอกให้อยู่ในรถตอนน้ำขึ้น เพราะโมเดลตอบจากความรู้ตัวเอง และเอกสารมีน้อยจนค้นไม่เจอ
  ตอนนี้คำตอบเรื่องความปลอดภัยมาจากเอกสารเท่านั้น เอกสารเพิ่มจาก 7 เป็น 10 เรื่อง และตัวค้นดึงคำแนะนำมาครบทั้งเรื่อง
  จาก 12 คำถามเรื่องความปลอดภัย สัดส่วนประเด็นที่ควรมีซึ่งอยู่ในข้อความที่ค้นได้ เพิ่มจาก **38% เป็น 80%**
- **เข้าสู่ระบบด้วย Google** ตรวจ ID token ด้วยกุญแจสาธารณะของ Google ต้องออกให้แอปเราและอีเมลยืนยันแล้ว
  อีเมลเดียวกับบัญชีเดิมจะเข้าบัญชีเดิม Google บังคับให้มีหน้า `/privacy` และ `/terms` ก่อนเปิดใช้จริง
  ผมจึงเขียนสองหน้านี้ด้วย พร้อมการตั้งชื่อที่แสดงและเปลี่ยนรหัสผ่าน
- **ถนนปิดจากกรมทางหลวง** (HDMS) แปลงเป็นหมุดภัย risk-decision นับเฉพาะจุดที่เส้นทางผ่าน วันที่ 4 ต.ค.
  เจอ 158 เหตุ และทำให้ทริปที่ผ่านนครสวรรค์กลายเป็น "ควรเลี่ยง" แต่บนเซิร์ฟเวอร์จริงไม่ได้ข้อมูลเลย
  เพราะ HDMS ตอบเฉพาะ IP ในไทย และเซิร์ฟเวอร์อยู่ต่างประเทศ ผมจึงปิดเป็นค่าเริ่มต้น (#104)
  และให้แชทพูดถึงถนนปิดเฉพาะตอนมีข้อมูลจริง
- **หน้าเว็บ** ใช้ตำแหน่งจริงแทนการแอบใช้กรุงเทพ ชื่อบนแผนที่ภาษาเดียว ค้นคำย่อมหาวิทยาลัยได้
  คอนทราสต์ธีมขาวที่วัดทุกหน้า เก็บฟอนต์ Noto Sans Thai ไว้ใน repo (เดิม build พังตอนโหลดฟอนต์)
  และบนมือถือ แผนที่เต็มจอ ปุ่มชั้นข้อมูลใหญ่ขึ้น เมนูไม่ล้นจอ และกันการดึงรีเฟรช (#104 → #105)

### 3. นำขึ้น main เอกสาร และการนำเสนอ (4–8 ต.ค.)

ทุกการแก้ไปจาก `dev` → `main` ผ่าน Pull Request ที่ CI ผ่านแล้ว เพื่อนในทีมดูแลเซิร์ฟเวอร์และ deploy `main`

ปัญหาที่เจอระหว่างพัฒนาพร้อมต้นเหตุ และข้อจำกัดตอนนี้พร้อมสิ่งที่ต้องทำถ้าจะแก้ หลังนำเสนอวันที่ 7 ต.ค.
ผมเพิ่มภาพหน้าจอจากเว็บจริง ผังโครงสร้าง เหตุผลที่ออกแบบแบบนี้ และวิธีวัดของทุกตัวเลข (#108 → #109)

## สิ่งที่แล็บนี้ยังพิสูจน์ไม่ได้

- ผล 33.8 → 3.9 วินาที วัดในเครื่องของผมด้วย image เดียวกันและจำกัด CPU กับแรมเท่ากัน ไม่ได้วัดบนเว็บจริง
  และการวางแผนกับแชทในรอบนั้นได้ประโยชน์จาก cache ของเส้นทาง
- ตัวเลข 38% → 80% นับคำสำคัญของประเด็นที่ควรมีในข้อความที่ค้นได้ วัดความครอบคลุม ไม่ได้วัดว่าคำตอบสุดท้ายถูกไหม
- ผลแชทขึ้นกับโมเดลและข้อมูลภัย ณ วันที่ถาม รันซ้ำวันอื่นอาจได้ไม่เท่ากัน
- ข้อมูลถนนปิดปิดอยู่บนเว็บจริง ผล 158 เหตุจึงใช้ได้กับเซิร์ฟเวอร์ที่อยู่ในไทยเท่านั้น
