# LAB04 — ปัญหาของระบบ RAG นี้ และสิ่งที่ทำกับมัน

[English](README.md) · ภาษาไทย

ปัญหาเก้าข้อที่พบในระบบถาม-ตอบแบบ RAG ใน [`../`](../) หนึ่งข้อต่อหนึ่งขั้นตอนของ pipeline
แต่ละข้อเขียนไว้ว่าเกิดอะไรขึ้น เพราะอะไร ตรวจสอบยังไง และการแก้ที่ทำไปแล้ว
หรือเหตุผลที่ยังไม่ได้แก้

ตัวเลขทุกตัวในนี้วัดจากระบบนี้จริง แต่ละข้อมีสคริปต์ที่ทำซ้ำปัญหาได้จากไฟล์ที่ repo นี้
commit ไว้อยู่แล้ว — chunk store, เวกเตอร์ FAISS, ดัชนี BM25 และผลการวัด
ไม่มีการดาวน์โหลดโมเดล และไม่ต้องใช้ API key

## วิธีรัน

```bash
cd LAB04/problems
python main.py        # เมนู
python main.py 4      # ดูข้อเดียว
python main.py 0      # ทั้งเก้าข้อ ใช้เวลาราวครึ่งวินาที
```

ไลบรารีใช้ของ LAB04 เดิม (`../requirements.txt`) ไม่ได้เพิ่มอะไรใหม่

## สิ่งที่ร้อยเก้าข้อนี้เข้าด้วยกัน

หกในเก้าข้อเป็นความล้มเหลวที่ไม่มี error ให้เห็น ขั้นแบ่ง chunk ไม่ทำอะไร
ฟิลด์หมวดไม่มีใครอ่าน ตัวแปลงคำถามกลืน exception ทุกตัว
โมเดลที่ถูกถอดออกทำให้ระบบถอยไปตอบด้วยข้อความดิบจากคลัง
รายการอ้างอิงถูกสร้างแล้วทิ้ง และสี่ในห้าของชุดข้อสอบแยกคอนฟิกไม่ออก
ทุกกรณีระบบยังทำงานต่อได้ และตัวเลขยังดูสมเหตุสมผล

นี่คือรูปแบบที่ควรจำไว้ใช้ต่อ — ใน RAG pipeline ความล้มเหลวที่อันตรายคือความล้มเหลวที่เงียบ
เพราะทุกขั้นมีทางถอยที่ดูสมเหตุสมผล และผลลัพธ์หน้าตาเหมือนคำตอบเสมอ
