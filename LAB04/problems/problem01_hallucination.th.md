# ปัญหาข้อ 01 — ตอบทั้งที่คลังไม่มีข้อมูลรองรับ

[English](problem01_hallucination.md) · ภาษาไทย · ทำซ้ำ: `python main.py 1`

## อาการ

จากคำถาม 20 ข้อใน `outputs/eval_generation.json` ระบบไม่เคยตอบว่าไม่รู้เลยสักครั้ง
และมีหนึ่งข้อที่ค้นไม่เจอ chunk ที่ถูกเลย แต่ยังเขียนคำตอบเต็ม ๆ พร้อมใส่เลขอ้างอิงให้ด้วย

| | |
|---|---|
| คำถามที่วัด | 20 |
| อัตราการตอบว่าไม่รู้ | 0.0000 |
| อัตราค้นเจอ chunk ที่ถูก | 0.9500 |
| correctness | 0.5957 |

ช่องว่างระหว่างอัตราค้นเจอ 0.95 กับ correctness 0.60 คือคำตอบที่เขียนขึ้นบนหลักฐานที่ไม่รองรับ

## สาเหตุ

มีด่านกันไว้สองชั้น และไม่ทำงานทั้งสองชั้น

`generator.py:84-89` คืน `NO_CONTEXT_MESSAGE` เมื่อ `chunks` ว่าง — ซึ่งไม่มีวันว่าง
FAISS ตอบคำถามแบบ "เพื่อนบ้านที่ใกล้ที่สุด" และเพื่อนบ้านที่ใกล้ที่สุดมีอยู่เสมอ
`vector_store.py:44` คืนเวกเตอร์ที่ใกล้ที่สุด `top_k` ตัวให้กับอินพุตทุกแบบ
ไม่ว่าจะเกี่ยวข้องหรือไม่ กิ่งที่ดักกรณีไม่มี context จึงไม่มีทางถูกเรียกในการใช้งานปกติ

กฎข้อ 2 ของ `SYSTEM_PROMPT` (`prompt_templates.py:16`) สั่งให้โมเดลปฏิเสธเมื่อข้อมูลไม่พอ
แต่นั่นคือคำขอที่เขียนเป็นภาษาไทย ไม่ใช่ข้อบังคับ จะทำตามหรือไม่เป็นดุลพินิจของโมเดล
และกับคำถาม 20 ข้อนี้ มันไม่เคยเลือกที่จะทำตามเลย

ระบบจึงไม่เคยมีกลไกสำหรับคำว่า "ไม่รู้" มีแต่คำแนะนำ

## วิธีตรวจสอบ

ถามเรื่องที่คลังไม่มีแน่ ๆ แล้วดูว่ามีคำตอบออกมาไหม
ส่วนในผลที่วัดไว้แล้ว ให้ดูสองฟิลด์นี้คู่กันใน `outputs/eval_generation.json`

- `อัตราการตอบว่าไม่รู้`
- `อัตราค้นเจอ chunk ที่ถูก`

ดูตัวเดียวไม่เห็นปัญหา — อัตราปฏิเสธเป็นศูนย์ดูเหมือนความมั่นใจ อัตราค้นเจอ 0.95 ดูเหมือนสำเร็จ
ที่เปิดโปงคือการดูเป็นคู่

## แนวทางแก้ที่ทำไปแล้ว

`serve.py:35` เพิ่มเกณฑ์ตัดไว้ก่อนถึง LLM โดยเทียบ cosine ของ dense hit อันดับ 1
กับเพดานที่กำหนดไว้ ถ้าต่ำกว่าก็หยุด ไม่ค้นต่อ ไม่ส่ง context ไม่แกล้งตอบ

```
RELEVANCE_MIN = 0.50
```

เพดานนี้มาจากการวัด ไม่ใช่การเดา — ใช้คำถามจริง 60 ข้อจาก `data/eval_paraphrases.txt`
เทียบกับคำถามนอกคลังที่เขียนขึ้น 20 ข้อ

| | |
|---|---|
| คำถามจริง ต่ำสุด | 0.5071 |
| คำถามจริง มัธยฐาน | 0.6469 |
| ปฏิเสธคำถามจริงผิด ที่เกณฑ์ 0.50 | 0 จาก 60 |
| จับคำถามนอกคลังได้ ที่เกณฑ์ 0.50 | 13 จาก 20 |

คะแนนที่ใช้ต้องมาจากขั้น dense เท่านั้น คะแนนของ reranker ใช้เป็นเกณฑ์ตัดไม่ได้
เพราะ cross-encoder ถูกฝึกให้เรียงลำดับ ไม่ได้ถูกฝึกให้สอบเทียบความมั่นใจ
มันให้ `"ช่วยหน่อย"` ถึง 0.8161 และ `"hello"` 0.7271 ขณะที่คำถามจริงบางข้อได้แค่ 0.0012
รายละเอียดอยู่ใน [ปัญหาข้อ 06](problem06_reranking.th.md)

เมื่อต่ำกว่าเกณฑ์ ระบบยังตอบให้ แต่ตอบด้วย prompt ทั่วไป (`GENERAL_PROMPT`, `serve.py:38`)
ในกล่องที่ติดป้ายแยกไว้ต่างหาก ผู้ใช้จึงเห็นได้ว่าคำตอบนี้ไม่ได้มาจากคลัง

## ที่ยังเหลืออยู่

คำถามนอกคลัง 7 จาก 20 ข้อได้คะแนนเหนือเกณฑ์ ทั้งหมดเป็นคำถามกว้าง ๆ ที่อยู่ในโดเมนจริง
แต่ไม่ได้ระบุอาการ

| คำถาม | คะแนน dense |
|---|---|
| โทรศัพท์พังทำยังไงดี | 0.6457 |
| คอมมีปัญหา | 0.6231 |

การปฏิเสธคำถามพวกนี้จะเป็นการทำผิด เพราะมันอยู่ในขอบเขตจริง สิ่งที่ควรทำคือถามกลับว่าอาการคืออะไร
ระบบยังไม่มีเส้นทางสำหรับการถามกลับ ตอนนี้จึงตอบไปตาม chunk 3 ชิ้นที่บังเอิญนั่งใกล้ที่สุด
