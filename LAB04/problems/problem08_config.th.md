## 1. น้ำหนักผสมไม่ใช่ค่าคงที่สากล

วัดบน variant paraphrase บันทึกไว้ใน `config.py:82-87`

| dense : BM25 | ปิด rerank | เปิด rerank | |
|---|---|---|---|
| 1 : 0 | 0.8961 | 0.9482 | ไม่ใช้ BM25 เลย |
| 1 : 0.5 | 0.7219 | 0.9482 | ค่าที่ใช้อยู่ |
| 1 : 1 | 0.6967 | 0.9496 | ค่าดั้งเดิมของสูตร RRF |
| 1 : 1.5 | 0.6165 | 0.7583 | |
| 0 : 1 | 0.4953 | 0.7583 | BM25 อย่างเดียว |

อ่านคอลัมน์ "ปิด rerank" จากบนลงล่าง ยิ่งเพิ่มน้ำหนัก BM25 ยิ่งแย่ลงทุกขั้น
การรวมตัวค้นสองตัวไม่ได้ดีกว่าตัวเดียวโดยอัตโนมัติ
คลังนี้คำถามกับคำตอบแทบไม่มีคำเฉพาะที่ตรงกันเป๊ะ BM25 จึงอ่อน
และการถ่วงน้ำหนักเท่ากันไปลากอันดับรวมให้ต่ำลง

คลังที่เต็มไปด้วยเลขรุ่น รหัสพาร์ต หรือชื่อเฉพาะจะให้ผลกลับกัน
ค่านี้ต้องวัดใหม่ทุกครั้งที่เปลี่ยนคลัง และห้ามลอกมาจากที่อื่น

เหตุผลที่ไม่ตั้งเป็น 0 ไปเลย: เมื่อเปิด rerank ค่าทุกค่าระหว่าง 0 ถึง 1
ให้ผลรายข้อเหมือนกันหมด เพราะตัวจัดอันดับใหม่เรียงผู้เข้ารอบทั้งชุดอยู่แล้ว
น้ำหนักนี้จึงมีความหมายเฉพาะตอนปิด rerank

## 2. ชื่อโมเดลที่ผู้ให้บริการถอดออก แล้วไม่มีอะไรฟ้อง

```python
LLM_PROVIDER = "groq"
LLM_MODEL    = "openai/gpt-oss-120b"
LLM_PROVIDERS["groq"] = (..., "llama-3.3-70b-versatile", "GROQ_API_KEY")
```

`generator.py:23` อ่านค่า `config.LLM_MODEL or default_model`
ถ้า `LLM_MODEL` ว่างเมื่อไหร่ ระบบจะถอยไปใช้ `llama-3.3-70b-versatile`
ซึ่ง Groq ถอดออกไปแล้วเมื่อ 18 สิงหาคม 2026 ค่าเริ่มต้นในตารางนั้นจึงตายแล้ว

ความล้มเหลวเงียบสนิท `get_llm()` ดัก exception แล้วคืน `NoLLM` (`generator.py:69-74`)
ระบบจึงตอบต่อได้ตามปกติ เพียงแต่คำตอบกลายเป็นข้อความดิบจากคลังโดยไม่มีโมเดลเข้ามาเกี่ยวเลย
และไม่มี error อะไรขึ้น

**วิธีตรวจ** เอาคำตอบที่ได้ไป grep ในไฟล์คลัง ถ้าเจอตรงตัวแปลว่า LLM ไม่ได้ทำงาน
หรือดูบรรทัด `[llm] Failed to use …` ใน log

**กติกาที่ได้จากเรื่องนี้** ก่อนเดโมทุกครั้งต้องยืนยันว่า LLM ทำงานจริง
อย่าถือว่า "มีคำตอบออกมา" เป็นหลักฐาน

## 3. สวิตช์แสดงผลที่ทิ้งงานที่ทำเสร็จแล้ว

```python
SHOW_SOURCES = False
```

`Generator.build_sources()` (`generator.py:113-123`) ประกอบรายการแหล่งอ้างอิงทุกครั้งที่ตอบ
ทั้ง chunk id คำถาม บรรทัดต้นทาง และคะแนน แล้ว `main.py` ไม่พิมพ์ออกมา เพราะสวิตช์นี้ปิดอยู่

ผู้ใช้เห็น `[1]` `[2]` ในคำตอบโดยไม่มีทางรู้ว่ามันหมายถึงอะไร
ซึ่งลบล้างเหตุผลทั้งหมดของการบังคับให้อ้างอิง

## 4. ค่าเริ่มต้นของขั้นหนึ่ง ปิดความสามารถของอีกขั้นอย่างเงียบ ๆ

```python
USE_QUERY_TRANSFORM = False
USE_MEMORY = True
```

ประวัติบทสนทนาไปถึงตัวปรับคำถามได้เฉพาะเมื่อ `USE_QUERY_TRANSFORM` เปิด
(`rag_pipeline.py:61-62`) ซึ่งค่าเริ่มต้นปิดไว้

`USE_MEMORY = True` จึงมีผลกับการเขียนคำตอบ ไม่มีผลกับการค้น
คำถามต่อเนื่องอย่าง "แล้วอันไหนดีกว่ากัน" ถูกส่งเข้าตัวค้นตามที่พิมพ์มาทั้งอย่างนั้น
แล้วได้เอกสารคนละเรื่อง

ลองเติมคำถามก่อนหน้าเข้าไปสองแบบแล้ววัดผล ไม่มีแบบไหนดีขึ้น
จึงคงพฤติกรรมเดิมไว้และเขียนข้อจำกัดนี้ลง README แทนที่จะปล่อยเงียบ
