# LAB02 — RAG Retrieval System (Thai Food Q&A)

ภาษาไทย · [English](README.md)

ระบบค้นคืนข้อมูล (retrieval) ที่สร้างทีละขั้นจากศูนย์บนคลังความรู้ภาษาไทย — อ่านไฟล์ `.txt`,
แบ่งเป็นชิ้น, ทำ embedding, เก็บเวกเตอร์ลง FAISS แล้วตอบคำถามด้วยการคืนข้อความที่ใกล้ที่สุด
คลังความรู้ของงานนี้คือคู่มืออาหารไทย 15 เมนู

งานนี้ทำตามโครงของใบงาน DL-03 โค้ดใน `src/` และ `labs/` เป็นของเทมเพลตอาจารย์ เปลี่ยนเฉพาะ
ชื่อไฟล์และคำถามทดสอบที่มันชี้ไป สิ่งที่เป็นของงานนี้จริง ๆ คือคลังความรู้ (`data/thai_food_qa.txt` เขียนขึ้นเอง),
คำถามที่ใช้ทดสอบ และตัวการรัน — สร้าง index แล้วตรวจว่าระบบค้นอะไรออกมาได้จริง
ข้อสังเกตทั้งหมดข้างล่างมาจากการรันนั้น

งานนี้เป็น retrieval อย่างเดียว ไม่มีขั้นตอนสร้างคำตอบ ระบบคืนคำตอบที่เก็บไว้ ไม่ได้เขียนคำตอบขึ้นใหม่

## คลังความรู้

`data/thai_food_qa.txt` มี 90 คู่ถาม-ตอบ — 15 เมนู เมนูละ 6 คำถาม ห้าคำถามแรกซ้ำกันทุกเมนู คือ
ที่มาและภาค, วัตถุดิบหลัก, รสชาติเด่น, ระดับความเผ็ด และเคล็ดลับ ส่วนคำถามที่หกต่างกันไป —
สิบเอ็ดเมนูถามวิธีทำ, สามเมนูถามเปรียบเทียบกับอีกเมนู (แกงเขียวหวานกับมัสมั่น, ต้มข่าไก่กับต้มยำ,
ผัดไทยกับผัดกะเพรา) และลาบหมูถามว่าปรุงรสด้วยอะไร เมนูทั้ง 15 คือ ต้มยำกุ้ง,
ผัดไทย, ส้มตำไทย, แกงเขียวหวานไก่, มัสมั่นเนื้อ, ข้าวมันไก่, ผัดกะเพราหมูสับ, ต้มข่าไก่,
ข้าวเหนียวมะม่วง, ลาบหมู, ข้าวซอย, แกงส้มชะอมกุ้ง, หมูปิ้ง, ขนมครก และยำวุ้นเส้น

รูปแบบไฟล์คือหัวข้อหมวดตามด้วยคู่ถาม-ตอบ คั่นด้วยบรรทัดว่าง

```text
[หมวด: ต้มยำกุ้ง]
Q: ต้มยำกุ้งใส่อะไรบ้าง วัตถุดิบหลักมีอะไร
A: วัตถุดิบหลักของต้มยำกุ้งได้แก่ กุ้งแม่น้ำหรือกุ้งทะเลตัวโต ตะไคร้ทุบ ...
```

ต้นทางเป็นไฟล์ข้อความ ไม่ใช่ PDF `document_loader.py` จึงบันทึกเลขบรรทัดของ `Q:` แต่ละคู่
แล้วส่งต่อไปถึง metadata ของ chunk นั่นคือสิ่งที่ใช้แทนเลขหน้าเวลาต้องย้อนกลับไปหาต้นทาง

## สิ่งที่ pipeline สร้างออกมา

| ขั้นตอน | ผลลัพธ์ |
|---|---|
| `lab01_extract_text.py` | อ่านได้ 90 รายการ แต่ละรายการมีหมวด คำถาม คำตอบ และ `line_no` |
| `lab02_chunking.py` | ได้ 90 chunk — คู่ละ 1 ชิ้น `CHUNK_SIZE` ตั้งไว้ 400 ตัวอักษร แต่ข้อความที่ยาวที่สุดยาว 314 (เฉลี่ย 225) ตัวแบ่งจึงไม่เคยได้แบ่งอะไรเลย |
| `lab03_create_embeddings.py` | `(90, 384)` float32 จาก `paraphrase-multilingual-MiniLM-L12-v2` normalize ตั้งแต่ตอน encode |
| `lab04_create_vector_db.py` | FAISS `IndexFlatIP` บนเวกเตอร์ 90 ตัว เพราะ normalize ไว้แล้ว inner product จึงเท่ากับ cosine similarity |
| `lab05` / `lab06` | แปลงคำถามหนึ่งข้อ ค้น แล้วพิมพ์ top-k |
| `lab07_complete_retrieval.py` | ส่ง 4 คำถามผ่าน `Retriever` เอา top-3 บันทึกลง `outputs/retrieval_results.json` |

หนึ่ง chunk ถูก embed ในรูป `Question: ... Answer: ...` คือเอาคำถามกับคำตอบมาต่อกัน ไม่ใช่คำตอบอย่างเดียว
คำถามที่คล้ายคำถามในคลังจึงถูกจับคู่ด้วยฝั่งคำถาม ซึ่งเป็นเหตุผลที่ index ขนาด 90 เวกเตอร์ยังพอใช้งานได้

`config.py` คำนวณทุก path จากตำแหน่งของตัวเอง ย้ายโฟลเดอร์ได้โดยไม่ต้องแก้อะไร

## ผลการค้นคืน

เอาคำถาม 10 ข้อใน `data/sample_questions.txt` ผ่านตัวค้นคืนเพื่อดูว่าระบบไปได้ถึงไหน
คะแนนคือ cosine similarity ของผลอันดับ 1

| คำถาม | คะแนนอันดับ 1 | ผล |
|---|---|---|
| ต้มยำกุ้งใส่อะไรบ้าง | 0.8279 | ถูก |
| เมนูไหนไม่เผ็ดบ้าง | 0.7312 | ผิด — ได้ "ผัดไทยเผ็ดไหม" |
| แกงเขียวหวานกับแกงมัสมั่นต่างกันยังไง | 0.7289 | ถูก |
| อาหารภาคอีสานมีเมนูอะไร | 0.6859 | ผิด — ได้ยำวุ้นเส้น ที่คลังระบุว่านิยมทั่วประเทศ ส่วนลาบหมูอยู่อันดับ 3 |
| ข้าวเหนียวมะม่วงทำยังไง | 0.7533 | ถูก |
| เมนูไหนเผ็ดที่สุด | 0.6594 | ผิด — ได้ "ผัดไทยเผ็ดไหม" |
| ข้าวซอยเป็นอาหารภาคไหน | 0.7448 | อันดับ 1 ผิด อันดับ 2 ถูก |
| ผัดไทยกับผัดกะเพราใช้เส้นเหมือนกันไหม | 0.6855 | ถูก |
| เมนูที่ใช้กะทิมีอะไรบ้าง | 0.5559 | ผิด — ได้ "ผัดไทยเผ็ดไหม" |
| ลาบหมูปรุงรสด้วยอะไร | 0.7826 | ถูก |

ถูกที่อันดับ 1 ห้าข้อจากสิบ และทั้งห้าข้อนั้นเป็นคำถามที่เจาะจงชื่อเมนูเดียว

แต่ห้าข้อนั้นมีอีกอย่างที่เหมือนกัน ซึ่งจำกัดว่าผลนี้พิสูจน์อะไรได้บ้าง — ทั้งห้าข้อมีอยู่ในคลังอยู่แล้ว
สามข้อตรงกับคำถามในคลังทุกตัวอักษร (แกงเขียวหวานกับแกงมัสมั่น…, ผัดไทยกับผัดกะเพรา…,
ลาบหมูปรุงรสด้วยอะไร) อีกสองข้อเป็นคำขึ้นต้นของคำถามในคลัง (ต้มยำกุ้งใส่อะไรบ้าง,
ข้าวเหนียวมะม่วงทำยังไง) ส่วนคำถามที่เรียบเรียงต่างจากในคลังจริง ๆ ตกไปอยู่ในกลุ่มที่ผิดทั้งหมด
การตรวจครั้งนี้จึงบอกได้แค่ว่าการจับคู่แบบเกือบตรงตัวใช้ได้ ไม่ได้บอกว่าระบบรับมือกับคำถามที่ถามใหม่
ด้วยสำนวนอื่นได้แค่ไหน เพราะในสิบข้อนี้ไม่มีข้อไหนเป็นแบบนั้นเลย

ส่วนห้าข้อที่ผิดแยกได้เป็นสองแบบ

**สี่ข้อเป็นคำถามข้ามเมนู** — เมนูไหนไม่เผ็ด, เมนูไหนใช้กะทิ, อาหารอีสานมีอะไรในคลังบ้าง
ไม่มีคู่ถาม-ตอบไหนตอบคำถามพวกนี้ได้ เพราะทุกเวกเตอร์คือคำตอบของเมนูเดียวต่อคำถามเดียว
ไม่มีอะไรใน index ที่สรุปรวมข้ามคลัง ตัวค้นคืนก็ยังคืนเพื่อนบ้านที่ใกล้ที่สุดมาอยู่ดี ที่ 0.56–0.73
ซึ่งไม่ได้ต่ำกว่าคะแนนของข้อที่ตอบถูกมากนัก และไม่มีจุดไหนใน pipeline ตั้งเกณฑ์ขั้นต่ำไว้
คำถามที่คลังตอบไม่ได้จึงหน้าตาเหมือนคำถามที่ตอบได้

**อีกหนึ่งข้อเป็นปัญหาการจัดอันดับ** คำถาม ข้าวซอยเป็นอาหารภาคไหน ได้คู่วัตถุดิบมาที่ 0.7448
ส่วนคู่ที่ตอบตรงคำถามจริง ๆ คือ ข้าวซอยเป็นอาหารภาคไหน มีที่มาอย่างไร ได้ 0.7113 จึงตกไปอันดับ 2
ทั้งคู่เป็นเมนูที่ถูก แต่ embedding แยก "ภาคไหน" กับ "วัตถุดิบ" ได้ไม่ชัดพอ และเพราะ `main.py`
พิมพ์เฉพาะอันดับ 1 ข้อนี้จึงกลายเป็นตอบผิดแทนที่จะเป็นเกือบถูก

## สิ่งที่เปลี่ยนจากเทมเพลต

- `data/thai_food_qa.txt` แทนที่ dataset ของเทมเพลต ของเดิมมี 391 คู่ในโดเมนอื่น
  ของงานนี้คือ 90 คู่ 15 เมนู เมนูละ 6 คำถาม เขียนขึ้นสำหรับงานนี้
- `data/sample_questions.txt` เพิ่มเข้ามาเองสำหรับทดสอบด้วยมือ ไม่มีสคริปต์ไหนอ่านไฟล์นี้ —
  มันคือคำถามที่พิมพ์ใส่ `main.py` เอง และเป็นที่มาของตารางข้างบน
- `config.py` ชี้ `SOURCE_FILE` ไปที่ dataset ใหม่ ส่วนข้อความ banner ใน `main.py`
  และคำถามทดสอบ 4 ข้อใน lab07 เขียนใหม่ให้เข้ากับโดเมน
- ที่เหลือใน `src/`, `labs/` และ `main.py` เป็นของเทมเพลตทั้งหมด รวมถึงค่าตั้ง —
  `CHUNK_SIZE` 400, `CHUNK_OVERLAP` 50, `TOP_K` 3 และโมเดล
  `paraphrase-multilingual-MiniLM-L12-v2`

## ข้อจำกัด

- **ไม่มีชุดวัดผล จึงไม่มีตัวเลขคุณภาพ** ตารางข้างบนคือคำถาม 10 ข้อที่ตรวจด้วยมือ ไม่ใช่การวัดผล
  และครึ่งหนึ่งใช้ถ้อยคำที่มีอยู่ในคลังอยู่แล้ว จึงทดสอบการถามด้วยสำนวนอื่นไม่ได้
  ไม่มี golden set ไม่มี hit@k หรือ MRR ในงานนี้ ส่วนนั้นอยู่ใน
  [`LAB04`](../LAB04/README.th.md) ซึ่งวัดการค้นคืนภาษาไทยอย่างจริงจัง
- **ใช้โมเดล embedding ตัวเดียว ไม่ได้เทียบกับตัวอื่น** ใช้ค่า default ของเทมเพลต
  ว่ามันเหมาะกับภาษาไทยหรือไม่ ไม่มีอะไรในโฟลเดอร์นี้ยืนยันได้
- **การแบ่ง chunk ยังไม่ถูกทดสอบที่ขนาดนี้** ไม่มีคำตอบไหนยาวเกิน 400 ตัวอักษร
  `text_splitter.py` จึงคืนข้อความเดิมทุกครั้ง ขั้นตอนนี้ทำงานแต่ไม่เคยได้ทำอะไรจริง
  คลังที่ใหญ่กว่านี้จะไปโดนเส้นทางโค้ดที่งานนี้ไม่เคยทดสอบ
- **`main.py` แสดงผลอันดับ 1 อย่างเดียว** `config.TOP_K` ตั้งไว้ 3 แต่ตอนเรียกส่ง `top_k=1`
  ทั้งบรรทัดนั้นและบรรทัดที่ถูก comment ทิ้งรอบ ๆ เป็นของเทมเพลตมาแต่เดิม
  และไม่มีเกณฑ์คะแนนขั้นต่ำ ระบบจึงตอบเสมอไม่ว่าจะห่างจากคำถามแค่ไหน
- **เป็น retrieval อย่างเดียว** คำตอบถูกคืนมาตรง ๆ จากคลัง ไม่มีอะไรเรียบเรียงคำตอบใหม่
