## อาการ

คลังคือ 15 เมนู เมนูละ 6 คู่ถาม-ตอบ และชื่อเมนูคือหมวดที่ติดอยู่กับทุก chunk
สแกนไฟล์ทั้งสี่บนเส้นทางค้นหา (`retriever.py` `embedding_model.py` `vector_store.py` `main.py`)

| | |
|---|---|
| บรรทัดที่ทำงานจริงและอ้างถึง `category` | 0 |
| บรรทัดที่ถูก comment | 1 — `main.py:30` |

```python
#print(f"Category: {item['category']}")
```

บรรทัดที่ถูก comment นี้มาจากโครงต้นฉบับของแล็บ ไม่ได้ถูกแก้ในงานชิ้นนี้
โค้ดใน `src/` และ `labs/` เหมือนต้นฉบับทั้งหมด ส่วนที่เป็นงานของแล็บนี้คือชุดข้อมูลอาหารไทย 90 คู่
สิ่งที่เขียนไว้ในโฟลเดอร์นี้จึงเป็นปัญหาของระบบตามที่มันเป็น ไม่ใช่รายการสิ่งที่ทำพลาดระหว่างทาง

ผู้ใช้จึงเห็นแค่ข้อความคำตอบ ไม่มีชื่อเมนู ไม่มีคำถามที่ตรงกัน
และไม่มีทางรู้ว่าระบบหยิบคู่ที่ถูกมาหรือเปล่า

## ราคาที่ต้องจ่าย

คำถามหกแบบซ้ำกันทั้ง 15 เมนู — *ใส่อะไรบ้าง* *เป็นอาหารภาคไหน* *เผ็ดไหม* *ทำยังไง* และอื่น ๆ
โครงประโยคจึงเหมือนกันหมดข้ามเมนู สิ่งเดียวที่แยกมันออกจากกันคือชื่อเมนูสั้น ๆ คำเดียว

**chunk 47 จาก 90 ชิ้น** มีเพื่อนบ้านที่ใกล้ที่สุดในคลังอยู่คนละเมนู ด้วยค่าความคล้ายที่สูงมาก

## ชื่อเมนูอยู่ในข้อความที่ embed ไหม

chunk 83 จาก 90 ชิ้นมีชื่อหมวดของตัวเองอยู่ข้างใน — แต่เป็นเพราะคำถามเอ่ยชื่ออาหารอยู่แล้วโดยธรรมชาติ
ส่วนอีก 7 ชิ้นใช้ชื่อแบบย่อ (`แกงเขียวหวาน` ในขณะที่หมวดคือ `แกงเขียวหวานไก่`)

ทั้งสองกรณีบอกเรื่องเดียวกัน — ชื่อเมนูอยู่ในดัชนีเป็นผลข้างเคียงของวิธีเขียนคำถาม
ไม่ใช่เพราะระบบใส่ให้ จึงพึ่งมันไม่ได้

## สิ่งที่ควรทำ

1. **เปิดบรรทัดที่ถูก comment ใน `main.py`** แก้บรรทัดเดียว ไม่ต้อง build ใหม่
   และทำให้ผู้ใช้ตรวจสอบคำตอบเองได้
2. **เติมชื่อเมนูเข้าไปในข้อความที่ embed** ต้อง build ใหม่และวัดผลใหม่
3. **กรองด้วยเมนูเมื่อคำถามเอ่ยชื่อเมนู** เมนูในคลังนี้แยกกันเด็ดขาด
   ความเสี่ยงจากการเดาผิดจึงต่ำกว่าคลังที่คาบเกี่ยวกันของ LAB04 มาก
