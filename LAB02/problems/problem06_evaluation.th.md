| | | |
|---|---|---|

## สิ่งที่มีแทน

`outputs/retrieval_results.json` มีคำถามสี่ข้อ มาจาก `SAMPLE_QUERIES`
ที่เขียนตายตัวไว้ที่ `labs/lab07_complete_retrieval.py:24`
มันบันทึกว่า **ระบบคืนอะไรมา** ไม่ได้บันทึกว่า **สิ่งที่คืนมานั้นถูกหรือผิด**
เมื่อไม่มีเฉลยให้เทียบ ก็คำนวณคะแนนอะไรจากมันไม่ได้

`data/sample_questions.txt` มีคำถามสิบข้อ และไม่มีสคริปต์ไหนเปิดไฟล์นี้
มีแต่ README ที่พูดถึงมัน ผลที่รายงานไว้ที่นั่นได้มาจากการรันด้วยมือแล้วอ่านผลเอง

## ทำไมถึงเป็นปัญหา

**ทำซ้ำไม่ได้** ตัวเลขที่รายงานไว้ตรวจสอบใหม่ด้วยคำสั่งเดียวไม่ได้
ต้องนั่งอ่านผลใหม่ทีละข้อ

**เปรียบเทียบไม่ได้** เปลี่ยนโมเดล เปลี่ยน `CHUNK_SIZE` หรือแก้คลัง
ก็ไม่มีตัวเลขก่อนหน้าให้บอกว่าดีขึ้นหรือแย่ลง

**ตัวเลขเดียวซ่อนข้อเท็จจริงสองเรื่อง** การนับด้วยมือมักได้ออกมาเป็น "ถูก 5 จาก 10"
ซึ่งซ่อนความจริงว่าคำถามเจาะจงเมนูได้ 6/6 ส่วนคำถามที่ต้องรวมหลายเมนูได้ 0/4
และไม่มีทางได้มากกว่านั้นเชิงโครงสร้าง ดู [ปัญหาข้อ 03](problem03_granularity.th.md)

## ทางแก้ที่เล็กที่สุดที่ได้ผล

คลังคือ 15 เมนูที่ใช้คำถามหกแบบเหมือนกัน จึงสร้างเฉลยอัตโนมัติได้
โดยใช้คำถามในคลังเป็นตัวตั้ง และให้ `chunk_id` ของมันเองเป็นคำตอบที่ถูก

แต่จะชนกับกับดักที่ LAB04 เจอเข้าเต็ม ๆ คำถามที่ลอกมาจากคลังตรง ๆ
ทำให้ทุกคอนฟิกได้ 1.0000 เท่ากันหมด และแยกอะไรไม่ออก
ต้องมีชุดคำถามที่เขียนใหม่ด้วยมือควบคู่ไปด้วย
ของ LAB04 ชุดนั้นมี 60 ข้อ และเป็นชุดเดียวที่ตัดสินอะไรได้
