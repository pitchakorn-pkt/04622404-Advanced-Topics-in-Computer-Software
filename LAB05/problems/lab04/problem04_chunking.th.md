# ปัญหาข้อ 04 — ขั้นแบ่ง chunk ไม่เคยทำงานเลย

[English](problem04_chunking.md) · ภาษาไทย · ทำซ้ำ: `python main.py 4`

## อาการ

`config.py` ตั้ง `CHUNK_SIZE = 400` กับ `CHUNK_OVERLAP = 50` และ `build_index.py:49`
เรียก `build_chunks()` กับทุก record วัดบนดัชนีที่ commit ไว้แล้วพบว่าตัวแบ่งไม่เคยแบ่งอะไรเลย

| | |
|---|---|
| record เข้า | 194 |
| chunk ออก | 194 |
| chunk ที่ `part_idx > 0` | 0 |
| chunk สั้นสุด | 306 ตัวอักษร |
| chunk ยาวสุด | 392 ตัวอักษร |
| ระยะห่างจาก `CHUNK_SIZE` | 8 ตัวอักษร |

`CHUNK_OVERLAP = 50` จึงไม่มีผลอะไรกับระบบนี้เลย และคอมเมนต์ปรับจูนใน `config.py:56-58`
อธิบายขั้นตอนที่ไม่ได้ทำงาน

## สาเหตุ

`split_text()` คืนข้อความทั้งก้อนทันทีเมื่อสั้นกว่าเกณฑ์ (`text_splitter.py:19-20`)
ส่วน `build_chunks()` ประกอบข้อความหนึ่งชุดต่อหนึ่งคู่ถาม-ตอบ เป็น `"Question: … Answer: …"`
(`text_splitter.py:41`) ซึ่งในคลังนี้ไม่มีคู่ไหนยาวถึง 400 ตัวอักษร

นี่ไม่ใช่บั๊ก หนึ่งคู่ถาม-ตอบเป็นหน่วยความหมายที่สมบูรณ์อยู่แล้ว การแบ่งมีแต่จะทำลาย
ปัญหาคือค่าตั้งประกาศพฤติกรรมที่ระบบไม่มี และไม่มีอะไรรายงานความไม่ตรงกันนี้

## ทำไมจึงเป็นความเสี่ยง ไม่ใช่ข้อบกพร่อง

chunk ที่ยาวที่สุดคือ 392 ตัวอักษร ห่างเกณฑ์แค่ 8 ตัว
เติมคำตอบที่ยาวกว่านี้เพียงข้อเดียว ตัวแบ่งจะเริ่มทำงานทันทีโดยเงียบ ๆ
และมันแบ่งด้วยการนับตัวอักษรล้วน ไม่สนขอบเขตประโยคหรือคำ

รัน `split_text()` กับคำตอบยาว 438 ตัวอักษร

```
ชิ้นที่ 0  (400 ตัวอักษร)
  ...ยไม่มีใครสังเกต แล้วรีสตาร์ตเครื่องหนึ่งครั้งเ
ชิ้นที่ 1  (88 ตัวอักษร)
  ๆ โดยไม่มีใครสังเกต แล้วรีสตาร์ตเครื่องหนึ่งครั้งเพื่อให้...
```

ชิ้นแรกจบกลางคำ ชิ้นที่สองขึ้นต้นกลางคำ ภาษาไทยไม่มีช่องว่างคั่น
การแบ่งด้วยการนับตัวอักษรจึงตกลงกลางคำบ่อยกว่าภาษาอังกฤษมาก
เศษพวกนี้กลายเป็นสัญญาณรบกวนตอนทำ embedding และอ่านไม่รู้เรื่องตอนส่งให้ LLM เป็น context

## วิธีตรวจสอบ

`python main.py 4` พิมพ์สองบรรทัดที่ตอบเรื่องนี้

- **chunk ที่ `part_idx > 0`** — ยังเป็น 0 แปลว่าขั้นนี้ยังไม่ทำงาน
- **ความยาวสูงสุด** — เข้าใกล้ `CHUNK_SIZE` แปลว่ากำลังจะเริ่มทำงาน

รันทุกครั้งหลังแก้คลังหรือแก้ `CHUNK_SIZE` เพราะ `build_index.py` ไม่รายงานให้
บรรทัดที่เคยพิมพ์จำนวน chunk ถูก comment ทิ้งไว้ (`build_index.py:51`)

## สิ่งที่ควรทำ

ทางเลือกที่ตรงกับคลังนี้ที่สุดคือไม่แบ่งเลย แล้วลบค่าตั้งที่ไม่มีผลออก
เพราะหนึ่งคู่ถาม-ตอบคือหน่วยการค้นที่ถูกต้องอยู่แล้ว

ถ้าจะเก็บขั้นนี้ไว้เผื่อคลังโตขึ้น ควรแบ่งตามขอบเขตประโยคแทนการนับตัวอักษร
และ `build_index.py` ควรพิมพ์จำนวนชิ้นที่ถูกแบ่งจริงออกมาทุกครั้ง
ตอนนี้ไม่มีสัญญาณอะไรบอกเลยว่าขั้นนี้ทำอะไรไป

ยังไม่ได้แก้ เพราะตัวเลขทุกตัวที่รายงานไว้ในแล็บนี้วัดบนดัชนีชุดปัจจุบัน
การเปลี่ยนวิธีแบ่ง chunk จะทำให้ตัวเลขทั้งหมดใช้ไม่ได้
