# ปัญหาข้อ 01 — ขั้นแบ่ง chunk ไม่ทำงาน และเกณฑ์ใหญ่กว่าที่โมเดลอ่านได้

[English](problem01_chunking.md) · ภาษาไทย · ทำซ้ำ: `python main.py 1`

## สองข้อค้นพบ

**ตัวแบ่งไม่เคยแบ่งอะไรเลย**

| | |
|---|---|
| record เข้า | 90 |
| chunk ออก | 90 |
| chunk ที่ `part_idx > 0` | 0 |
| chunk ยาวสุด | 314 ตัวอักษร |
| `CHUNK_SIZE` | 400 ตัวอักษร |

`split_text()` คืนข้อความทั้งก้อนเมื่อสั้นกว่าเกณฑ์ และไม่มีคู่ถาม-ตอบไหนในคลังนี้ยาวถึง 400
`CHUNK_OVERLAP = 50` จึงไม่มีผลอะไรกับระบบนี้เลย

**เกณฑ์ที่ตั้งไว้ใหญ่กว่าช่องรับของโมเดล** วัดด้วย tokenizer ของโมเดลเองบน chunk ทั้ง 90 ชิ้น

| | |
|---|---|
| โมเดล | `paraphrase-multilingual-MiniLM-L12-v2` |
| `max_seq_length` | 128 โทเคน |
| โทเคนของ chunk | ต่ำสุด 47 · สูงสุด 113 · เฉลี่ย 73.7 |
| chunk ที่เกินเพดาน | 0 จาก 90 |
| chunk ยาวสุด | 314 ตัวอักษร = 113 โทเคน |
| อัตราส่วนที่ได้ | 2.78 ตัวอักษรต่อโทเคน |
| 128 โทเคน ≈ | 356 ตัวอักษร |
| `CHUNK_SIZE` | **400 ตัวอักษร** — เกินที่โมเดลอ่านได้ 44 |

วันนี้ยังไม่มีอะไรถูกตัด เพราะไม่มี chunk ไหนเข้าใกล้ 400
แต่ค่าที่ตั้งไว้อนุญาตให้มี chunk ที่โมเดลอ่านไม่หมด ถ้าวันหนึ่งมีขึ้นมา
ส่วนท้ายจะถูกตัดทิ้งก่อนเข้าโมเดลอย่างเงียบ ๆ — sentence-transformers ตัดให้โดยไม่ throw error
chunk นั้นจะค้นเจอได้ด้วยเนื้อหาครึ่งแรกเท่านั้น ในขณะที่ยังแสดงให้ผู้ใช้เห็นเต็ม ๆ

## ทำไมถึงสำคัญทั้งที่ยังไม่พัง

ค่าสองตัวนี้ขัดกันเอง และไม่มีอะไรตรวจ
ตัวหนึ่งนับเป็นตัวอักษร อีกตัวนับเป็นโทเคน ความขัดแย้งจึงมองไม่เห็น
จนกว่าจะมีใครแปลงหน่วยให้ตรงกัน ซึ่งเป็นสิ่งที่สคริปต์นี้ทำ

## วิธีตรวจสอบ

รัน `python main.py 1` หลังแก้คลังทุกครั้ง แล้วอ่านสามบรรทัด

- **chunk ที่ถูกแบ่ง** — ยังเป็น 0 แปลว่าขั้นนี้ยังไม่ทำงาน
- **ความยาวสูงสุดเป็นตัวอักษร** — เข้าใกล้ `CHUNK_SIZE` แปลว่ากำลังจะเริ่ม
- **ความยาวสูงสุดเป็นโทเคน** — เข้าใกล้ 128 แปลว่ากำลังจะเริ่มถูกตัด

## สิ่งที่ควรทำ

ตั้ง `CHUNK_SIZE` ให้ต่ำกว่าเพดานจริงของโมเดล — ราว 300 ตัวอักษรสำหรับโมเดลตัวนี้กับข้อความไทย
ค่าปัจจุบันสัญญาสิ่งที่โมเดลทำไม่ได้

หรือเปลี่ยนไปใช้โมเดลที่รับได้ยาวกว่า LAB04 ใช้ `BAAI/bge-m3` ซึ่งรับ 8192 โทเคน
