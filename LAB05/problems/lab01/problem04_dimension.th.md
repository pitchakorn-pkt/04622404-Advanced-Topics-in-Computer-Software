# ปัญหาข้อ 04 — เวกเตอร์ที่สร้างคนละแบบเทียบกันไม่ได้

[English](problem04_dimension.md) · ภาษาไทย · ทำซ้ำ: `python main.py 4`

## เงื่อนไขที่ต้องเป็นจริง

การค้นคือการเทียบเวกเตอร์ของคำถามกับเวกเตอร์ที่เก็บไว้
การเทียบนั้นมีความหมายก็ต่อเมื่อทั้งคู่มาจาก **provider** **model** และ **dimension** เดียวกัน
เวกเตอร์ไม่ได้บอกว่าใครสร้างมัน — ตัวเลข 384 ตัวจาก bge กับจาก Gemini หน้าตาเหมือนกันทุกประการ
ระบบจึงต้องพกข้อมูลนี้ไปเอง

## ด่านสองชั้นที่มีอยู่

**`embedding_settings()`** (`vector_store.py:140-150`) ยืนยันว่า record ทุกอันใน collection
บันทึกโมเดลและความกว้างเดียวกัน รันกับข้อมูลที่ปนกัน

| อินพุต | ผล |
|---|---|
| ตรงกันหมด | ผ่าน — `BAAI/bge-small-en-v1.5` · 384 |
| คนละโมเดล | หยุด — `records were embedded with several models: [...]` |
| คนละความกว้าง | หยุด — `records have several dimensions: [384, 1536]` |

**ความกว้างของ collection** `create_collection()` เขียน dimension ลง metadata ของ collection
(`vector_store.py:232-233`) แล้ว `upsert()` เทียบทุก batch กับค่านั้น (`vector_store.py:248-255`)
เพราะ Chroma ไม่บังคับ schema ของความกว้างเอง เวกเตอร์ 1536 มิติที่ใส่เข้า collection ของ 384
จะไม่ถูกปฏิเสธโดยตัวมันเอง

นี่คือเหตุผลที่การเปลี่ยน provider ต้องใช้ collection คนละอัน

```bash
python Pipeline/05_embedding.py --provider gemini --dimension 1536
python main.py --build --collection job_postings_gemini \
                       --persist-dir Pipeline/chroma_gemini
```

## ช่องที่ยังเหลือ

provider เป็นการ **สันนิษฐาน** ไม่ใช่การตรวจ `vector_store.py:64` บันทึกไว้ว่า
collection ที่ไม่ได้บอกจะถูกถือว่าถูก embed มาด้วยอะไร

collection ที่สร้างด้วย provider อื่นแต่ความกว้างบังเอิญตรงกันจะผ่านด่านทั้งสองข้างบน
แล้วการค้นจะทำงานต่อโดยไม่มี error เลย ผลที่ได้ไม่ใช่ความล้มเหลว
แต่เป็นคะแนนความคล้ายที่ไม่มีความหมาย เพราะสองปริภูมิเวกเตอร์ที่ไม่เกี่ยวกันถูกนำมาวัดระยะกัน
และผลลัพธ์หน้าตาเป็นผลการค้นปกติทุกอย่าง

นั่นคือความล้มเหลวที่ยากกว่าในสองแบบ ความกว้างไม่ตรงทำให้ upsert พังและเห็นทันที
ส่วน provider ไม่ตรงไม่ทำให้อะไรพัง มันแค่ทำให้คำตอบแย่ลง

## วิธีตรวจสอบ

ถามคำถามที่รู้คำตอบอยู่แล้ว ถ้าคะแนนอันดับ 1 ต่ำผิดปกติและผลที่ได้ไม่เกี่ยวกับคำถามเลย
ให้สงสัยเรื่องนี้ก่อนสงสัยคุณภาพคลัง แล้วเทียบ metadata ของ collection กับค่าที่ record บันทึกไว้

## สิ่งที่จะแก้ได้

เขียน provider ลง metadata ของ collection แบบเดียวกับที่ทำกับ dimension แล้วเทียบตอนค้น
เปลี่ยนการสันนิษฐานให้เป็นการตรวจสอบ

## หมายเหตุเรื่องการรัน

`vector_store.py` import `chromadb` ซึ่งอยู่ใน `LAB01/requirements.txt` (`chromadb==1.5.9`)
แต่ไม่ได้ติดตั้งไว้ใน `.venv` ที่ repo นี้ใช้ร่วมกับแล็บอื่น
สคริปต์จึงดึงตัว `embedding_settings()` จริงออกมาจากไฟล์ต้นฉบับแล้วรัน แทนการ import ทั้งโมดูล
โค้ดที่ถูกรันจึงเป็นโค้ดตัวจริง ไม่ใช่สำเนา
