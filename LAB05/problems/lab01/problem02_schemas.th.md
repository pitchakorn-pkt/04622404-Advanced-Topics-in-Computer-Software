# ปัญหาข้อ 02 — สอง schema และฟิลด์ที่กฎทำให้ว่างเปล่า

[English](problem02_schemas.md) · ภาษาไทย · ทำซ้ำ: `python main.py 2`

## สอง schema ในคลังเดียวกัน

| แหล่ง | record | ชนิดของ id | ฟิลด์ข้อความ |
|---|---|---|---|
| aidevboard_ai | 20 | `str` — `'48720738-0f4b-483d-…'` | `description` |
| jobicy_cyber_security | 28 | `int` — `149591` | `jobDescription`, `jobExcerpt` |
| jobicy_devops_infra | 32 | `int` | `jobDescription`, `jobExcerpt` |
| jobicy_software_en | 100 | `int` | `jobDescription`, `jobExcerpt` |

Jobicy ใช้ camelCase กับ id ที่เป็นจำนวนเต็ม ส่วน AIDevBoard ใช้ snake_case กับ id ที่เป็น UUID
ทั้งคู่ใช้คีย์ชื่อ `id` เหมือนกัน

เรื่องนี้เห็นได้ก็ต่อเมื่อเปิดดูข้อมูลจริง โค้ดที่เขียนจากสเปกจะเห็นแค่ schema เดียว
แล้วอีกแหล่งจะผ่านขั้นทำความสะอาดไปทั้งอย่างนั้นโดยไม่มี error ใด ๆ
เพราะ `process_records()` แก้เฉพาะฟิลด์ที่มีอยู่จริง (`cleaning.py:130-131`)
record ที่ชื่อฟิลด์ไม่ตรงจะถูกคัดลอกไปทั้งก้อน

ข้อค้นพบนี้ถูกส่งให้ทีมเป็นคอมเมนต์ใน pull request แทนที่จะจัดการเงียบ ๆ
เพราะขั้น chunking ที่อยู่ถัดไปก็อิงชื่อฟิลด์ชุดเดียวกัน

## ฟิลด์ที่กฎทำให้ว่างเปล่า

`jobExcerpt` คือย่อหน้าเปิดของ `jobDescription` ซึ่งมักเป็นคำโฆษณาบริษัท
การนับมันเป็นเอกสารของตัวเองทำให้ข้อความเดียวกันถูกนับสองครั้งต่อประกาศหนึ่งฉบับ
มันจึงข้ามเกณฑ์ห้าเอกสารได้ง่ายขึ้น แล้วถูกตัดทิ้ง

| | boilerplate | excerpt ที่ว่างเปล่า |
|---|---|---|
| นับ `jobExcerpt` เป็นเอกสารด้วย | 80 บรรทัด | **30 จาก 160** |
| ไม่นับ (ที่รันจริง) | 77 บรรทัด | 0 จาก 160 |

ต้องยกเว้นสองที่ และทำไว้ครบทั้งสอง

1. ยกเว้น `jobExcerpt` จากการ **ถูกตัด** — `KEEP_BOILERPLATE_FIELDS` (`cleaning.py:31`)
2. ยกเว้นมันจากการ **ถูกนับ** ด้วย — `02_data_cleaning.py:50-56`

ถ้าทำแค่ข้อแรก ฟิลด์จะไม่ว่าง แต่ข้อความในนั้นจะยังไปดันให้บรรทัดของ `jobDescription`
ข้ามเกณฑ์เร็วกว่าที่ควร สองแถวข้างบนคือส่วนต่างนั้นพอดี

## การยกเว้นอีกข้อ และเหตุผล

บรรทัดที่ยาวไม่เกินสี่คำจะไม่ถูกตัดเลย ไม่ว่าจะซ้ำบ่อยแค่ไหน (`cleaning.py:36`)
เพราะมันคือหัวข้ออย่าง `Requirements` หรือ `The Role` และขั้น chunking ใช้มันเป็นขอบเขตในการแบ่ง
chunk ทุกชิ้นในคลังนี้ถูกสร้างด้วย `strategy: heading`

ตัดหัวข้อทิ้งเมื่อไหร่ ขั้นถัดไปจะแบ่งผิดที่ทันที
เป็นตัวอย่างเล็ก ๆ ว่าการตัดสินใจในขั้นหนึ่งผูกกับขั้นถัดไปแน่นแค่ไหน

## วิธีตรวจสอบ

นับตัวบ่งชี้เชิงโครงสร้างก่อนและหลังทุกขั้น และ diff ชื่อฟิลด์ของแต่ละแหล่งก่อนเขียนโค้ดจับมัน
ตัวรันตรวจเชิงโครงสร้างไว้แล้ว — `02_data_cleaning.py:30-39` ยืนยันว่าไม่มี record ไหน
เสีย `id` ไป ไม่มีคีย์เพิ่มหรือหาย และค่าที่ไม่ใช่ข้อความไม่เปลี่ยนเลย
